# Electron Stories and Audiobooks

> **Historical context:** this page was written while the Electron and Tauri apps
> coexisted. Mentions of Tauri helpers, pages, tests and regression results describe
> that migration period; the Tauri shell has since been removed and the shared code
> now lives in `electron/src/shared/`. Existing Tauri installs: see the
> [migration guide](electron-migration.md).

Stories and Audiobook are available from the sidebar and command search. Each keeps a separate draft. Choose a saved default voice, enter or import text, then render. Stories supports per-line voice overrides; chapter headings and pause markup use the same `storyToSpans` compiler as Tauri. Audiobook submits the original script to the existing backend parser.

Plain-text audiobook imports recognize chapter-title lines with LF, CRLF or CR line endings. Manuscripts with existing Markdown H1 headings retain their explicit structure and original text.

Both editors use the shared longform backend, real chapter progress, assembly status, and an explicit Stop action. Progress reaches inside a chapter too: while one renders the SSE stream carries `progress` events (`index`; `phase` — `loading` while the voice model loads, `queued` while another job holds every GPU worker, then `rendering` with `done` of `total` takes to render, `phrases` when they are sentences, and `rate`, the wall-clock seconds one take takes, its speech check and retakes included). They go straight to the stream, never into job history, whose cap would push out the chapter events a resume reads. The panel names what the chapter waits for or its sentences done, moves its bar inside the chapter, and counts the time left from the takes left at their pace — the chapters after it at the pace finished chapters went, or, before any has, at this one's — so even a one-chapter book has a time left after its first takes. Stop aborts the HTTP stream: the backend cancels the chapter in progress, which stops after its current take, and schedules no more chapters. A truncated stream cannot replace the last successful output. Interrupted server manifests can be resumed explicitly without sending the edited manuscript again; Resume finishes the render in the book it belongs to (its project is opened first), and a render started before the library finishes in a new book of its own. Navigation leaves a render running; a renderer restart disconnects it and recovery uses the server manifest inventory.

Playback and export remain independent of generation. Vidstack plays the output; long-form audio uses a seek bar without decoding an entire book into a waveform. Play waits until the native media provider is ready. MP3 and M4B are supported by the existing backend. The native export dialog saves a local copy, written to disk as it downloads so a long book never has to fit in memory; an existing file is replaced only once the new copy is complete, and an unfinished save is removed when it fails or the app quits. A finished render also offers a chapter cue sheet — a `.txt` of `HH:MM:SS<TAB>Title`, one line per chapter — for show notes, podcast platforms and players that do not read the chapters M4B embeds and MP3 cannot carry. Its timestamps are summed from the exact per-chapter milliseconds the backend writes into the M4B chapters, over only the chapters that rendered, so they match the embedded chapter starts (shown in whole seconds, hours unbounded); a chapter that failed contributes no line and no elapsed time. The file is saved through the native save dialog. Each render also writes `<output>.timeline.json` beside the book (`GET /audiobook/timeline/{output}`; the SSE `done` event carries `timeline: true`): every chapter's start and end, its sections, and each phrase's text, voice and start/end in seconds, measured from the samples actually joined; a phrase that starts a new line or paragraph of the script carries `break: "line" | "paragraph"` (format version still 1 — readers ignore keys they do not know). Chapters reused from a cache that predates timelines, or rendered by an older remote worker, are marked `chapter` precision and the reader estimates their words; a 404 means the book has no timeline. **Export HTML** (`POST /audiobook/export/html`) builds a ZIP in the app’s data folder (`html_exports`) — a self-contained `index.html` with no network requests, the audio (M4B as `.m4a`) and the cover — and the app saves it the same way through `GET /audiobook/export/html/{id}`, which serves it once and removes it, so no second copy of the book stays behind (a save that is cancelled or fails discards it at once through `DELETE /audiobook/export/html/{id}`; a browser download that never finished is removed by the next export after an hour, and whatever is left when the backend starts is removed then; one an earlier version left beside the book goes with the next export or render). The page follows the rendered timeline, or one estimated from the script for books rendered before timelines existed. Its own words are in the app's language and direction; the book's text is tagged with the book's language (unknown for **Auto**), and a chapter the script left untitled is named in the app's language.

The page sets the text itself — chapters, paragraphs, sections, contents, each phrase a `<span class="ph" data-s data-e>` — so it reads and prints without script; its one inline script times each phrase's words and drives the player. Its look is the export request's `design` (`services/book_templates.py`): a template — `classic`, `modern`, `magazine`, `cinematic`, `kids` or `script` — plus quick options (`accent` `#rrggbb`, made readable on every theme; `body_font` and `heading_font`, a bundled family or `system`; `show_names`; `numbering` `words | numeral | roman | none`), every missing or unknown choice falling back to the template's own; `GET /audiobook/export/html/templates` lists the templates with their defaults and swatches. `POST /audiobook/export/html/preview` takes the same request and answers `{html}` — the first chapter (the one after a headless opening too), cut short, no script or audio, the cover inline, the first phrase shown lit — for the dialog's `sandbox=""` `srcdoc` frame, which runs nothing under the renderer's CSP; it writes nothing. The page embeds only the families its design names, as base64 WOFF2 `@font-face` rules (a page opened from disk cannot load a font file beside it in every browser), italics only where the template sets them. The fonts live in `backend/assets/fonts/<family>/` with each family's `OFL.txt`; `manifest.json` (family, category, files with style, weight range, size and SHA-256, licence) is the one source of truth, written by `scripts/build_book_fonts.py` from a pinned google/fonts commit (Latin, Latin Extended and Vietnamese subsets; families with a Reserved Font Name — in their `OFL.txt` or in a font's own copyright and licence records — ship whole, only recompressed). `GET /fonts` lists them and `GET /fonts/{family}/{file}` serves a listed font or licence (the reader loads its book's body font through it, with `FontFace`); packaging copies them with the backend (`electron/tests/packaging-contract.mjs` checks every listed file). A request with `voice_names` (profile id → name) names a book's voices; a profile id with no name is never shown. A story posts `story` — its chapters as `/longform/render` posted them, which the draft keeps with its finished file (`outputStory`; a render from before falls back to the story's lines as they stand) — which marks it a story (Script by default) and, for a story rendered before its timeline said who reads each line, gives its phrases their `speaker` and line breaks (`timeline_with_turns`, as `timeline_with_layout` gives a book its paragraphs), or an estimated timeline when it has none (chapter lengths that do not match its chapters are dropped for the file's length, shared by their text). `/longform/render` spans may carry `break_before` (a new line of the story) and `speaker` (`{name, accent}`: the character and its cast slot, the Stories editor's colour): display only, never a take or cache key, kept by the resume manifest, and carried onto the rendered timeline's phrases.

Draft writes reuse the coalesced persistence helper and flush on lifecycle events. Every Stories and Audiobook draft belongs to a project in a library kept in the shared native IndexedDB adapter (a separate Electron database, one record per project plus a small summary record, so a record that cannot be read costs only that project). The page header names the open book with its save state (*Saved*, *Saving…*, *Save failed — retry*) and opens the library: search, open, new, rename, duplicate and delete (confirmed; rendered audio files are never deleted with a project). Edits save themselves a second after the last change, and at once when another book is opened, the page is hidden or closed, or a render starts; a new book becomes a project ("Untitled book N", or its title) on its first edit, and its name follows the title until it is renamed. Switching books is refused, with the reason, while that editor renders. The working draft from before the library, and projects saved by earlier versions, join the library the first time it is used — a draft that was already saved updates that project instead of making a duplicate. After that the library is the book of record: at start-up a working copy replaces its project only when it holds newer edits, so a working copy left behind by a full browser storage or a crash never overwrites newer saved work. A project also keeps what each of its recent renders was shown with (script, chapter lengths, speech check, levels), so opening an older render and then the latest again loses nothing. Projects include script/lines, voices, settings and the finished output they show. Storage failures are surfaced. Book details include author, narrator, year, genre, description and an uploaded JPEG/PNG cover. Loudness offers off, ACX and podcast presets. A preset masters the joined book in two loudnorm passes to its integrated target (ACX −19 LUFS, podcast −16 LUFS) and keeps the chapters' own sample rate (without it the encoder kept loudnorm's 192 kHz as 96 kHz AAC or 48 kHz MP3, a larger file whose peaks landed over the ceiling). The limiter aims 0.5 dB under the preset's true-peak ceiling (ACX −3.0 dBTP, podcast −1.5 dBTP), since AAC and MP3 encoding pushes peaks back up, and the encoded file is metered (`ebur128`): one still over its ceiling — low bitrates overshoot most — is encoded again with that much more headroom, at most three encodes in all. ACX MP3 is written the way ACX accepts it: 44.1 kHz at a constant 192 kbps, or the higher bitrate asked for. Audiobook pronunciation rows reach the existing lexicon engine; duplicate words are flagged before rendering. These settings persist with the draft. Full cast management and other advanced controls remain tracked in `electron/PARITY.md`.

`electron/tests/longform-smoke.mjs` verifies the main flows with mocked generation and real audio playback. Runtime tests cover stop, duplicate prevention, truncated responses, explicit resume and shared Stories compilation. Real installed-model verification passed for one English chapter: MP3 rendering, cached WAV chapter audition, and Electron-driven M4B rendering/playback. Multi-voice, multi-chapter, cancellation/recovery and other engines still require real runtime coverage.

Script voice tags now expose saved-profile assignments in the Cast section. The default voice and every cast name are chosen from the same searchable voice picker; a name's first option, *uses Default voice*, removes its assignment. `[voice:]` and `[voice:default]` (in any case) read in the book's default voice, so they are not listed for casting nor sent in `voice_map` — except a `[voice:Default]` a saved draft already cast to a profile (earlier versions allowed it), which keeps reading in that profile and stays in the Cast panel until its assignment is removed. In Stories, `[voice:]` returns to the line's own voice while `[voice:default]` reads in the default voice, and the tag card says which. Word counts split Chinese, Japanese and Thai at their word breaks. Only names present in the current script are sent as `voice_map`; assignments persist for reuse if a tag is reintroduced. An assignment to a removed profile blocks rendering until changed or reset to Default. Chapter, word and estimated runtime counts reuse the Tauri script helpers.

The Audiobook **Contents** rail, on the left of the editor frame (folded to a toggle by the viewer, or over the editor in a narrow window), lists the script's chapters (`# Title`) and sections (`## Title`, `### Title`) as the parser reads them, moves the editor caret to a heading and scrolls the editor (never the page), and renames, adds or removes headings as undoable editor edits. The text before the first heading is the intro, with an **Add title** action that inserts a `# ` heading above it. `POST /audiobook/outline` reports each chapter's status through the render's own cache-key derivation: rendered, changed since the last book (whose timeline records each chapter's cache key), or not rendered; a test renders a book through `/audiobook` and checks that every chapter then reads as rendered. Read sentence by sentence, a chapter rendered here and not cached whole also carries `takes: {total, cached}` — how many phrase takes it reads and how many a render would reuse, decided as the render decides (a segment cached whole by an earlier version counts for all its takes; once one of them is retaken, for the others it can be cut into) and read from one listing of the take and segment folders per request — so the rail adds **N sentences to render**, or **All sentences ready** when a render only joins the takes again, beside a chapter that must render again and already has sentences rendered. Those keys also hold the steps of the Settings → Performance preset, the active TTS engine and whether the chapter renders on a worker, so changing the preset or the compute target from the status bar, or the engine from the page's engine notice, asks for the statuses again, and a render started before the new answer arrives leaves the old cached flags out of its time left. The parser names an untitled chapter "Chapter N" for the file's chapter marks, so every reply that carries a chapter title — the plan, the outline, a chapter preview, the SSE `chapter`/`chapter_error` events and the timeline — adds `untitled: true` beside it, and the app names that chapter in its own language; a render summary's `chapter_titles` keeps it blank, and a book without a title is not named after it. Each chapter's play button is a per-chapter audition. Auditions send the same voice, cast, language and pronunciation inputs as full renders, warming the shared cache. Auditions — a chapter's, a passage's (Listen) and a Stories line's — render one at a time and Generate waits for the one rendering, while the editor, the cast and the settings stay open. A chapter or passage audition asks `POST /audiobook/preview` with `stream: true` and shows its progress (the render's `progress` events, then `done` carrying the JSON answer, or `error`; a backend from before answers once, without progress) with Stop beside it, which ends the render on the backend after the take in progress; without `stream`, and for `/generate`, the backend notices a client that went away just the same. A chapter audition is tied to its own chapter's text and the settings that reach it: typing in another chapter leaves it current, and one whose chapter changed while or after it rendered is kept, marked **Outdated** (named as it was when it rendered) — so is one rendered under another active engine, Settings → Performance preset (its steps and postprocessing, from `GET /audiobook/sampling`) or, for a book that follows it, Settings → Reading. While a chapter audition renders with the rail folded, the toggle says so. Preview requests are aborted on navigation and when another book opens (its auditions go with it), never replace a full render, and expose their own Vidstack playback.

Production overrides now expose synthesis steps, guidance, sampling temperatures, postprocessing, seed and repeat variation. Emotion controls appear when the active engine advertises support. Reset restores the shared Tauri defaults; untouched fields are omitted from requests, and the steps slider and postprocessing switch then show what a render will use — the steps of the Settings → Performance preset, 16 at Balanced (`GET /audiobook/sampling`). The extracted `longformOverrides` helper is used by both apps, and chapter auditions carry the same overrides as full renders. Seamless-join controls (gap between lines, gap between paragraphs, trim engine silence) live in the same panel; untouched or reset controls show the preserved server defaults (zero gaps, trimming off). Set gaps and enable trimming explicitly for seamless joins; see `docs/expressive-speech.md`.

Run `electron/tests/longform-live.mjs` with `VOICESTUDIO_LIVE_PROFILE` set to a local saved profile for an explicit real-render check. It verifies the active model is already installed before synthesis. The real run exposed missing JSON request headers in the shared client and array-shaped failed-chapter results; regression tests now cover both.

Stories now includes named characters with saved voice assignments, character selection per line, explicit per-line voice overrides, shared/global speed and per-line speed overrides. The book-wide speed sits in the setup card beside voice and language (not inside the Cast card); it counts the lines that carry their own speed and hands them back to the book-wide value in one click. Voice resolution and chapter compilation reuse the Tauri helpers. Lines move up/down with keyboard-accessible buttons; chapter insertion uses the same heading grammar. A story with every spoken span assigned can render without an unnecessary default-voice selection. Removed profiles block rendering rather than silently changing the voice.

Stories Auto-cast accepts tagged dialogue, screenplay text and attributed prose. The shared local parser appends lines, reuses existing characters/voices, and assigns available profiles to new speakers. Distinct names that normalize to the same identifier remain separate characters. No network or LLM call is involved.

A Stories script can also be built from a finished dub, which replaces the current script, cast and pending import with the dub's speakers and lines. The action lives in the Dub workspace; see `docs/electron-dubbing.md`.

WebVTT (`.vtt`) captions also import locally; their cue metadata is dropped before the spoken lines enter Stories.

Stories imports TXT, Markdown and SRT locally; EPUB/PDF still use the shared backend importer. The EPUB importer skips marked pagination and ancillary sections such as cover, title, dedication, contents and copyright pages. Unmarked pages are judged by the book's own structure: only a short, heading-less, unlisted page ahead of the reading start is skipped, even when an EPUB 2 guide or EPUB 3 landmark declares that start; headed or substantial unlisted prologues are retained; the same kind of stray page is skipped at the back only once back matter that the contents lists has begun, so an unlisted file that continues the last chapter is always kept. Publisher and bibliography headings such as “Published by” and “Novels by” are skipped only on short, unlisted pages before the reading start; an ambiguous heading alone (for example “Works”) is not enough to delete a section. Unmarked numeric paragraphs and page-break layout classes remain narration. Chapter titles prefer the EPUB 3 table of contents, then NCX labels and headings; namespace aliases and declared encodings are supported. Malformed optional navigation falls back to headings, while malformed package/container XML reports an import error. Imported text goes into a persisted review buffer, then Auto-cast or Split into lines appends to existing work. The splitter is shared with the browser app and offers three presets: Sentences (the sentence-aware splitter with the same 40-2000 character limit), Paragraphs (the default; one line per blank-line paragraph, or per line when the text has no blank lines at all; LF, CRLF and lone-CR endings are all understood) and Chapters (one line per chapter body, split only at chapter headings — a non-empty `# Title`, the same grammar the renderer uses). A chapter heading is always its own line so it renders as a chapter marker.

The Electron workspace keeps title, default voice, language and output format together in a fixed setup card. Advanced cast, production and book controls use separate collapsed cards; the project library lives in the page header. The editor keeps its full working width; an empty Story shows one Add First Line action, while an empty Audiobook shows the supported chapter and voice markup directly in the script field.

Stories line auditions reuse the shared WAV assembler and canonical voice/pause/speed parser. Auditions resolve inline names with the same fallback as full renders, read at the steps a full render takes (the draft's own, else the Settings → Performance preset's from `GET /audiobook/sampling`; they used to read at a fixed 32), expose Stop — the `/generate` request they make stops its render after the take in progress once its client goes away — and play through Vidstack independently. An audition whose own line or the story's settings changed stays, marked **Outdated**, as does one rendered under another engine, Settings → Performance preset or (for a story that follows it) Settings → Reading; typing in another line leaves it current; navigation, or opening another story, aborts pending auditions, and so does deleting, clearing or turning into a chapter heading the line being auditioned, whose Stop goes with it. Browser coverage verifies actual playback with mocked generation.

The optional Stories Stems section renders one WAV per character with the shared Tauri assembler. It reports completed character groups, supports cancellation, and offers explicit individual downloads after completion. No automatic multi-file download is triggered. Input changes discard stale download links. Browser regression checks all character groups and the downloaded WAV bytes. The shared native Save As bridge writes renderer-generated bytes in packaged Windows and Linux builds; macOS remains the native export gate.

EPUB local manifest and navigation links support percent-encoded filenames, including spaces and Unicode. Percent escapes are decoded once; literal plus signs remain part of the filename.

EPUB chapters honor byte-order marks and XML/HTML encoding declarations, including
legacy Latin and CJK encodings. Unsupported or invalid declarations use the shared
text-import fallback so one bad declaration does not abort the book.

EPUB decompression limits include required metadata as well as navigation and chapter content. A navigation document without a navigation element falls back to chapter headings.

### Long-script layout

The Stories editor grows with the manuscript inside the page scroll container. Generate/Stop, the chapter tracker and the render status live in a footer pinned to the setup pane, so the primary action and its progress stay visible however long the script is; with the setup pane collapsed the same panel sticks to the bottom of the editor instead. When Generate is unavailable the panel states the first reason (import running, a preview rendering, engine not ready, no spoken lines or script, a line with no voice and no default voice, a name cast to a deleted voice, a duplicated pronunciation word) and the button looks unfinished (dashed) rather than greyed out. Pressing it lists every missing piece under a Voice engine → Script → Default voice (Stories: a voice for every line) → Cast checklist, the Cast step only while the script names voices; each item scrolls to, focuses and briefly highlights the control that fixes it — the engine notice, the script, the default voice picker, the name cast to a deleted voice, or the repeated pronunciation word. An import, the other mode's render or a preview is the only reason given while it runs. A word typed twice in Pronunciation is marked invalid; the outline and previews read the first row meanwhile, and a render refuses the book until the copy is removed.

### Clear a script

Stories and Audiobook offer **Clear script** with confirmation. Stories removes all lines, chapter markers and pending import text while retaining the cast; Audiobook clears its manuscript. The web Stories editor clears pending pasted text too, stops playback, ignores late preview results and releases preview audio when clearing, removing or replacing lines. Confirmation also names pending imported text. Clearing an imported script does not recreate the demo story.

The pinned chapter tracker scrolls within the available setup-pane height, keeping Stop reachable in compact windows. Collapsing setup moves the controls into the editor; they remain visible while scrolling long scripts.
SRT and WebVTT manuscript imports preserve spoken numbers, including countdowns and numeric-only cues; cue indices, timestamps, the `WEBVTT` header, NOTE/STYLE/REGION blocks and cue identifiers are removed.
Projects lists the same books and stories as the editor's library, one entry per book with its renders grouped under it (*7 renders*, expandable); ▶ plays the latest. Clicking a book, or one of its renders, opens it in the editor with that render's audio ready. A render records the library project it came from (`project_id` on the render request and in `GET /longform/jobs`); a render made before the library is matched to the book that showed its file, and otherwise opening it creates a project rebuilt from the text its reading timeline kept (markup tags are not kept) — a render without a timeline cannot be opened and says so. Finished renders identify themselves: a one-line recipe (voice · speed · engine · length), and **How it was made** expands to voice, speed, engine, language, format, size and the non-default settings. Renders made before this was recorded say so instead of showing a bare filename.

Render history includes effective sampling settings (including performance-tier defaults). Non-finite request values are rejected; older malformed numeric details are sanitized so Projects and completion events remain readable.

The output language picker in Clone, Stories and Audiobook disables languages outside the selected engine’s declared finite set. Auto remains available; unknown or model-specific language sets remain selectable and are checked by the backend. Reference recording languages and dubbing translation targets are independent of this output-language control. Switching engines preserves the selected language rather than rewriting saved projects.

The finished-render library filters for Stories and Audiobooks before applying its row limit, so newer dubbing jobs cannot hide an older finished book.

Resuming starts a fresh job while preserving the original checkpoint until all chapters render successfully. Checkpoint writes and syncs are best effort, so an interrupted resumed job can leave both the original and new checkpoints available; either can reuse the shared chapter cache. Closing an unstarted response or interrupting the render leaves the original plan available, including when a replacement checkpoint could not be saved. A render with no failed chapters retires the original even if the replacement checkpoint could not be saved. A partial output keeps the original plan available to retry its failed chapters.

With sentence-by-sentence reading (Settings → Reading, on by default) the cache keeps every sentence's take on its own, beneath the chapter and segment layers (a segment is one run of script in one voice): `longform_cache/takes/` holds each take as the engine returned it, written the moment it finishes, and a chapter not cached whole is put together from its takes. Plain prose parses to one segment per chapter, so a cache of whole segments rendered every take of a chapter again for a one-word edit and lost every finished take of a stopped render; now an edit renders only the takes whose spoken text changed (after normalization, the pronunciation lexicon and `[[word|respelling]]` overrides — a new lexicon entry renders only the takes it respells), a stopped or crashed render loses at most the take in progress, and a passage or chapter audition reuses and warms the same takes. A take is keyed by the voice it resolves to, its spoken text, speed, the take-level options (`ExpressiveOptions.TAKE_LEVEL`: steps, guidance, temperatures, postprocessing, seed, emotion, repeat variation), the language, and which repeat of that same take in its chapter it is, so every repeat of a sentence has a take of its own. Every other option is assembly-level (`ExpressiveOptions.ASSEMBLY_LEVEL`; a test fails on a field in neither): changing the punctuation pauses, trimming, the gaps, voice leveling or a volume joins the cached takes again without rendering any — the comma rule and the paragraph gap reach a take only where they change its text — and turning the speech check on listens to the cached takes, each heard once, its score kept with the take, rendering again only takes that fail — a retake the check chose is kept in a slot of its own, so a render without the check still reads every take as first rendered. The chapter WAVs stay; a segment read sentence by sentence is no longer stored whole as well, so the takes are not a third copy of the book's audio in the cache. Segments and chapters cached whole by earlier versions keep being reused; the first edit of a chapter cached that way renders it once more, take by take from then on, and a retake in a segment cached whole cuts its other takes from it by the take ranges kept with it (`longform_render.cuttable_takes`) — so does a passage preview that reads takes from it — so only the retaken take renders. **Retake one sentence:** `POST /audiobook/takes` (a chapter preview's body) lists the chapter's takes in reading order — `span` (its segment's index in `/audiobook/plan`'s spans of that chapter), `take` (its index in that segment, as the rendered timing counts it), `text` (as the reader shows it), `retake` and `cached` (whether a render would reuse it, a segment cached whole by an earlier version included) — and `POST /audiobook/retake` with the same body plus `span`, `take` and optionally `phrase` (refused with 409 when the take there now says something else) counts one more retake for it, kept in `longform_cache/takes/retakes.json` with where the take is read: the three takes on each side of it and its chapter's title, as digests (no script text). A render places each retake on the take it was asked for by those surroundings (`longform_render.chapter_takes`: most of them must still be there, and more than where the chapter starts or ends), so the same sentence read in another chapter or book keeps its take and key, an edit around it keeps the retake, and a copy of the sentence added or removed before it neither takes nor drops it. The retake is cached under a salt of its own, which also seeds it anew when the voice pins one; only the chapter it is placed in changes key. Each save is flushed to the disk, with the retakes as they were kept in `retakes.prev.json` and read when the file is torn. `POST /longform/takes` and `POST /longform/retake` do the same for a Stories chapter, posted as `chapter` (one of `/longform/render`'s `chapters`) with the render's voices, cast, language and options. A remote worker renders whole chapters, so a retake there renders the chapter again: the task names each take the worker must read otherwise than it plans the chapter (`takes`: `[[span, take, occurrence, salt], …]`, sent only when there is one, so every other chapter keeps its remote key), and the worker seeds every take by the rule this computer seeds by (`services.audiobook.take_seed_input`), so with a voice that pins its seed the retaken sentence comes back anew, every other as before, and a chapter sounds the same wherever it renders. A worker without the `audiobook_takes_v1` feature is refused at registration. In both editors, right-clicking a sentence offers **Retake this sentence** (**Retake N sentences** for every take a selection reaches), and the card of a reaction, delivery or respelling offers it for the sentence around the tag; the editor finds each listed take in its text by the characters the reader shows (markup aside, a take of tags alone at its own line of tags) and asks for it with its text as `phrase`; `tests/fixtures/retake_take_cases.json` holds both sides to one corpus, the backend's lists in pytest and the editor's placements in Vitest. Audiobook then plays the paragraphs holding the retaken takes, asks the Contents rail again and puts away a chapter preview of that chapter; Stories says the next render reads them anew. A preview rendering at that moment reads the take as it was: a passage preview, or a preview of the retaken chapter, stops, and the paragraphs play once it has; a preview of another chapter renders on, and the editor says the next render reads the retake. A retake asked for while another is being saved waits its turn instead of being dropped, and when a sentence cannot be looked up (the backend did not answer) the editor says why rather than that there is no sentence there. A passage preview (Listen) sends `context` with the passage — its chapter's script text, heading included, and where the passage starts and ends in it — so its takes are named as the chapter names them (`longform_render.passage_takes`): a sentence the chapter said earlier is the repeat it is there, a retake asked for in the chapter plays, and the preview renders only the takes the book has not cached. The action is offered only where the book reads sentence by sentence and its voices are ready.

Cache pruning evicts the least recently used chapter, segment and take audio, including interrupted partial files, while retaining JSON bookkeeping needed to locate older cache entries after moving the data directory, and the retakes asked for. Every chapter, segment or take a render or audition reuses counts as used — chapters served whole from the cache used to keep the age they were written with, so a book larger than the cache (2 GB by default, `OMNIVOICE_LONGFORM_CACHE_MAX_GB`) lost the chapters it kept reusing first — so a book keeps the audio it reuses and loses what edits superseded. Pruning runs before each render, off the backend's event loop, and never removes the chapters a running render has finished and has yet to join into its book, nor the segments and takes a chapter it is rendering may read: they are held from the moment the chapter starts. Bookkeeping contributes to the reported cache size; if it alone exceeds the budget, pruning remains best effort.

Cache keys follow what the engine actually receives. The steps (and postprocessing) of a Settings → Performance preset key the audio rendered with them — before, a chapter rendered at 64 steps replayed at 16 — at every preset, Quality and no preset chosen included, so audio rendered now is never keyed like the request alone; and a remote worker renders at the same preset. A span is keyed by the voice it resolves to, not by the whole cast, so recasting one name re-renders only that voice's lines, and chapters it does not speak in stay cached. The gap between lines is added between finished takes, so changing it joins the cached takes again without rendering them. Audio cached under the earlier keys is still found and moved to the new ones, so upgrading re-renders nothing (a chapter cached before presets keyed it is kept for whichever preset first asks for it), and the Contents rail reads a book rendered under the earlier keys as unchanged. The one exception is a language the engine now receives otherwise: the default model used to read the pickers' Arabic, both Chinese scripts, Kurdish, Haitian Creole, Kyrgyz, Pashto, Punjabi, Tagalog and region tags such as pt-BR as Auto, and Confucius4, Supertonic-3, CosyVoice, dots.tts and MOSS-TTS-v1.5 were sent some languages in spellings they misread (German reached Confucius4 as "ge", "cmn-Hans" MOSS-TTS-v1.5 as a name it does not know); a chapter in such a language renders again once, all of its takes, so an edit never joins takes read without the language to takes read with it (`LANGUAGE_INPUT_RENDER` in `backend/services/language_codes.py`). A chapter already cached is served without loading the model, also one whose takes wait for a recognizer while none is installed. With the speech check on, what it found is kept with each chapter, segment and take, so a cached or partly re-rendered chapter still lists the sentences to listen to; takes it could not listen to (no recognizer installed, or one that heard no words in them or could not run) are recorded as unchecked, never as checked — reused as they are while no recognizer answers, and checked by the first render after one does; the speech-check report under the book, and under a passage preview, says how many sentences were not checked and why: it asks to install a recognizer only when none is installed, and otherwise asks to listen to them, naming their chapters. A chapter rendered on a remote worker is never checked, so the check does not change its cache key (see `docs/remote-workers.md`).
